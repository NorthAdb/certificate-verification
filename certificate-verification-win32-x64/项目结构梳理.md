# 证书验证工具 — 项目结构梳理

> 基于 `certificate-verification-win32-x64` 目录分析，聚焦证书查看与验证功能。  
> 应用类型：**Electron 桌面程序**（产品名：证书验证），通过 `child_process.exec` 调用 **GmSSL** 命令行完成操作。

---

## 1. 项目总览

| 项目 | 说明 |
|------|------|
| 技术栈 | Electron 9.x + 原生 HTML/JS（无框架） |
| 入口 | `resources/app/main.js` → 加载 `index.html` |
| 核心逻辑 | 全部在 `resources/app/index.html` 的内联 `<script>` 中 |
| 密码学引擎 | `gmssl.exe` + `libcrypto-1_1.dll` + `libssl-1_1.dll` |
| 打包形态 | electron-packager 输出的 win32-x64 绿色发行包 |

上层仓库 `20240429certificate-verification` 还包含：

- `certificate-verification-win32-x64/` — **本工具（唯一有实际代码的部分）**
- `openspec/` — OpenSpec 配置（仅 `config.yaml`，无业务代码）
- `.cursor/` — Cursor 技能与命令配置
- `PKI实验.pdf`、`数字证书验证工具.pptx` — 文档资料

**结论：** 真正需要维护的源码只有 3 个文件：`main.js`、`index.html`、`package.json`（外加图标 `ic.ico`）。

## 3. UI 界面与按钮命令对照

界面分为四个区域，对应 `index.html` 中的四段 `<p>` 标题。

### 3.1 根证书

| UI 元素 | 绑定函数 | 是否调用 gmssl | 命令模板 |
|---------|----------|----------------|----------|
| **选择文件** | `inputRootCert()` → 触发隐藏 `<input type="file" id="inputFile">` | 否 | — |
| **查看证书** | `viewRootCert()` | **是** | `gmssl x509 -in <根证书路径> -noout -text` |

- 路径来源：`document.getElementById("inputFile").files[0].path`
- 显示路径：`#inputFileAgent`（只读文本框）

### 3.2 CRL

| UI 元素 | 绑定函数 | 是否调用 gmssl | 命令模板 |
|---------|----------|----------------|----------|
| **选择文件** | 内联 `document.getElementById('inputFile2').click()` | 否 | — |
| **查看CRL** | `viewCrl()` | **是** | `gmssl crl -in <CRL路径> -noout -text` |
| **验证CRL** | `verifyCrl()` | **是** | `gmssl crl -in <CRL路径> -CAfile <根证书路径> -noout` |

- CRL 路径：`#inputFile2` → `files[0].path`
- 根证书路径：`#inputFile` → `files[0].path`
- 验证 CRL 需要同时选择根证书和 CRL

### 3.3 要验证的证书

| UI 元素 | 绑定函数 | 是否调用 gmssl | 命令模板 |
|---------|----------|----------------|----------|
| **选择文件** | 内联 `document.getElementById('inputFile1').click()` | 否 | — |
| **查看证书** | `viewCert()` | **是** | `gmssl x509 -in <待验证证书路径> -noout -text` |
| **验证证书** | `verifyCert()` | **是** | 见下方条件分支 |

**验证证书** 命令逻辑（`verifyCert()`）：

```
若未选择 CRL（#inputFileAgent2 为空）：
  gmssl verify -CAfile <根证书路径> <待验证证书路径>

若已选择 CRL：
  gmssl verify -CAfile <根证书路径> -verbose -crl_check -CRLfile <CRL路径> <待验证证书路径>
```

- 待验证证书路径：`#inputFile1` → `files[0].path`
- CRL 为可选项；有 CRL 时额外做吊销检查

### 3.4 OCSP

| UI 元素 | 绑定函数 | 是否调用 gmssl | 命令模板 |
|---------|----------|----------------|----------|
| **OCSP URL** 输入框 | `#inputOcspUrl` | 否 | — |
| **查询OCSP** | `queryOcsp()` | **是** | `gmssl ocsp -issuer <根证书路径> -cert <待验证证书路径> -text -url <OCSP_URL>` |

- 需要：根证书 + 待验证证书 + OCSP URL 三者齐全

### 3.5 命令汇总表

| 按钮 | gmssl 子命令 | 完整命令示例 |
|------|-------------|-------------|
| 查看证书（根） | `x509` | `gmssl x509 -in root.pem -noout -text` |
| 查看CRL | `crl` | `gmssl crl -in crl.crl -noout -text` |
| 验证CRL | `crl` | `gmssl crl -in crl.crl -CAfile root.pem -noout` |
| 查看证书（待验证） | `x509` | `gmssl x509 -in cert.pem -noout -text` |
| 验证证书（无CRL） | `verify` | `gmssl verify -CAfile root.pem cert.pem` |
| 验证证书（有CRL） | `verify` | `gmssl verify -CAfile root.pem -verbose -crl_check -CRLfile crl.crl cert.pem` |
| 查询OCSP | `ocsp` | `gmssl ocsp -issuer root.pem -cert cert.pem -text -url http://ocsp.example.com` |

### 3.6 命令执行方式

所有 gmssl 调用统一模式：

```javascript
const exec = require('child_process').exec
workerProcess = exec(cmdStr, {})
workerProcess.stdout.on('data', (data) => alert(data))
workerProcess.stderr.on('data', (data) => alert(data))
```

- 输出通过 `alert()` 弹窗展示（无专用结果面板）
- 使用 `nodeIntegration: true`（Electron 9 旧写法，存在安全风险）

### 5.1 高优先级 — 明显冗余，删除不影响功能

| 路径 | 建议 |
|------|------|
| 根目录 `demoCA/` 与 `resources/app/demoCA/` | **保留一份**，建议统一到 `resources/app/demoCA/` 或单独 `samples/` |
| 根目录 `crl.crl`、`chain.pem`、`baidu.pem` | 移入 `samples/` 示例目录，或删除 |

### 5.3 低优先级 — 依赖与工程化

| 项 | 说明 |
|----|------|
| `package.json` 中 `jquery`、`require` | 未在代码中使用，可移除 |
| `child_process` 列为 devDependency | Node 内置模块，不应作为 npm 依赖 |
| `index.html` 第 6 行 `var gmssl = './gmssl.exe '` | **已声明但未使用**；实际命令写的是裸 `gmssl`，依赖 PATH 而非本地路径 |
| Electron 9.1.1 | 版本过旧（2020），存在已知 CVE；建议升级 |
| `node_modules/` | 打包后为空壳，开发时需 `npm install` |

### 5.4 不建议删除

| 路径 | 原因 |
|------|------|
| `locales/*.pak` | Chromium 界面语言包 |
| `chrome_*.pak`、`icudtl.dat`、`snapshot_blob.bin` 等 | Electron 运行时必需 |
| `resources/app/gmssl.exe` + DLL | 核心依赖 |
| `resources/app/main.js`、`index.html` | 唯一业务代码 |

## 6. 代码质量问题（清理/重构时关注）

### 6.1 gmssl 路径未正确使用

```javascript
// index.html 第 6 行 — 定义了但未使用
var gmssl = './gmssl.exe '

// 实际命令 — 使用裸命令名，在部分环境下可能找不到 gmssl
let cmdStr = 'gmssl x509 -in ' + c + ' -noout -text'
```

**建议：** 统一使用 `path.join(__dirname, 'gmssl.exe')` 或在主进程封装执行函数。

### 6.2 校验后未中断执行

`verifyCrl()`、`verifyCert()`、`queryOcsp()` 在 `alert()` 提示缺少文件后**没有 `return`**，仍会继续 `exec()`，可能因 `files[0]` 为 `undefined` 而报错。

### 6.3 大量重复代码

6 个功能函数的结构几乎相同（exec + stdout/stderr alert），可提取为公共 `runGmssl(cmd)` 函数。

### 6.4 路径含空格未加引号

文件路径直接拼入命令字符串，路径含空格时会失败。应使用引号包裹或 `execFile` 传参数数组。

### 6.5 安全设置

`nodeIntegration: true` 且未启用 `contextIsolation`，不符合现代 Electron 安全实践。

## 8. 本地开发与运行

```bash
cd certificate-verification-win32-x64/resources/app
npm install
npm start          # 启动 electron .
```

打包发行使用 electron-packager（从 `package.json` 的 name `packager` 推断），产物即为当前 `certificate-verification-win32-x64` 目录形态。
